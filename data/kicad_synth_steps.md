# KiCad Synthetic PCBA Dataset Protocol

This project uses a reproducible KiCad-first dataset for classical reference-based PCBA assembly and solder inspection. The generator creates golden renders, camera/background robustness tests, edited KiCad assembly variants, PNG-level solder defects, ROI files, ground truth files, and a manifest for batch evaluation.

## One-Command Dataset Generation

Use the generator from the repo root:

```powershell
python -m src.kicad_synth_dataset generate --output data\kicad_synth --seed 3130
```

Useful variants:

```powershell
python -m src.kicad_synth_dataset generate --output data\kicad_synth --boards board01 --force
python -m src.kicad_synth_dataset validate --manifest data\kicad_synth\manifest.json
python -m src.kicad_synth_dataset clean-images --output data\kicad_synth
```

The generator assumes KiCad 9 CLI at:

```text
C:\Program Files\KiCad\9.0\bin\kicad-cli.exe
```

Override it if needed:

```powershell
python -m src.kicad_synth_dataset generate --kicad-cli "C:\Program Files\KiCad\9.0\bin\kicad-cli.exe"
```

## Dataset Contents

Per board, the generator targets:

- 1 golden white render and 1 transparent source render.
- 12 defect-free registration/background cases: 4 camera variants times 3 backgrounds.
- 6 assembly defect cases: missing, shifted, and rotated components for two selected SMD components.
- 8 solder defect cases: bridge, insufficient, excessive, and missing solder for two selected two-pad components.

Target scale for four boards: about 104 cases.

Camera variants:

```text
identity
shift_pan: --zoom 0.85 --pan 1.2,0.8,0
rotated_5deg: --zoom 0.85 --rotate 0,0,5
shift_rotate: --zoom 0.85 --pan 0.8,-0.6,0 --rotate 0,0,-4
```

Background variants used in the dataset:

```text
white
blue_mat
noisy_lab
```

Additional backgrounds remain available through `src.background_augment`: `black`, `gray_gradient`, and `warm_desk`.

## ROI and Ground Truth

The generator parses each KiCad PCB file to extract:

- front-side footprints;
- reference names;
- footprint positions and rotations;
- front-side SMD pad positions and sizes;
- Edge.Cuts board bounds.

It selects suitable visible R/C/D/LED/Q/U-style SMD components, derives component boxes from pad extents, and derives solder-joint boxes from individual pad boxes. The board millimeter-to-pixel mapping is estimated from Edge.Cuts bounds and the transparent render alpha mask.

ROI schema:

```json
{
  "board_id": "board01",
  "image_size": [2400, 1800],
  "components": [
    {
      "id": "R1",
      "bbox": [622, 38, 80, 93],
      "type": "Resistor_SMD:R_0603_1608Metric",
      "expected_angle": -90.0
    }
  ],
  "solder_joints": [
    {
      "id": "R1-P1",
      "component_id": "R1",
      "bbox": [634, 79, 55, 42]
    }
  ]
}
```

Ground truth schema:

```json
{
  "case_id": "board01_missing_R1",
  "defects": [
    {
      "id": "gt1",
      "defect_type": "missing_component",
      "bbox": [622, 38, 80, 93],
      "component_id": "R1"
    }
  ]
}
```

Registration/background cases have an empty `defects` array.

## Batch Evaluation

Run the full generated manifest:

```powershell
python -m src.run_dataset_eval --manifest data\kicad_synth\manifest.json --output-dir outputs\kicad_synth_eval --verbose
```

Outputs:

```text
outputs\kicad_synth_eval\
  summary.csv
  metrics.json
  summary.md
  cases\
    <case_id>\
      aligned_test.png
      defect_overlay.png
      report.json
      evaluation.json
```

Course acceptance targets:

- Overall F1 score at least 0.70 on generated defect cases.
- Defect-free registration false-positive rate at most 10%.
- Per-class recall at least 0.70 for missing component, shifted component, rotated component, and solder bridge.
- At least 8 representative overlay images saved for presentation figures.

## Classical Image Processing Story

This dataset and pipeline deliberately avoid deep learning. The final report and presentation should emphasize:

- board localization and registration by board masks, ORB features, homography, and phase correlation;
- spatial enhancement with LAB CLAHE, histogram matching, and bilateral filtering;
- frequency-domain high-pass and band-pass filtering for fine wiring/component detail;
- color segmentation in HSV/Lab spaces for solder and metallic regions;
- morphology and connected-component analysis for mask cleanup and shape measurement;
- template matching for component inspection;
- rule-based fusion and classification for interpretable AOI results.

## Background Randomization Note

Even without deep learning, a classical pipeline can overfit to a clean background. Background randomization tests whether board localization, segmentation, and registration depend on PCB content rather than the surrounding desk/mat/noise.

Relevant references:

- KiCad CLI PCB render documentation: https://docs.kicad.org/9.0/en/cli/cli.html#pcb-render
- Tobin et al., "Domain Randomization for Transferring Deep Neural Networks from Simulation to the Real World": https://arxiv.org/abs/1703.06907
- Sensors 2021, "Generating Images with Physics-Based Rendering for an Industrial Object Detection Task: Realism versus Domain Randomization": https://www.mdpi.com/1424-8220/21/23/7901
